# Design

## Context

动机见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| 应用侧规模 | `deep_research_harness/src/deerflow_deep_research/`：**49 个模块** |
| 先期取证 | 用现成算法扫**整棵包树**：**零环**（故扩围后真实树仍绿） |
| 治理侧的导入风格 | 目录在 `sys.path` 上 ⇒ 绝对名 = 同目录名（`from gitio import …`） |
| 应用侧的导入风格 | 包根在 `src/` ⇒ 绝对名从 `deerflow_deep_research.` 起（`from deerflow_deep_research.domain import bundle`） |
| 关键差别 | 治理侧"绝对基准 = 模块根"是**巧合**；应用侧两者**不同**（`src/` vs 包目录） |

## Goals / Non-Goals

**Goals:** 一条规则服务两种导入风格 · 既有治理侧判定一字不变 · 应用侧真实树绿（已取证）·
应用侧形态能红 · 体积表跟实测。

**Non-Goals:** 不改应用侧任何代码 · 不做跨 scope 的环 · 不改既有规则语义。

## Decisions

### D-1｜scope 显式建模为 `(module_root, absolute_base)`

- **选**：`Scope(module_root, absolute_base)`；绝对点号名从 `absolute_base` 解析，解析结果**必须落在
  `module_root` 内**才算图内节点。
- **为什么**：治理侧两者相同、应用侧不同（`src/` vs 包目录）。若照搬治理侧的写法，应用侧的
  `from deerflow_deep_research.domain import bundle` 会被解析成
  `…/deerflow_deep_research/deerflow_deep_research/domain.py` —— **不存在**，于是**全部绝对导入
  被静默漏掉**，规则看起来在跑、实际只覆盖相对导入。这是"静默失守"，比报错更坏。
- **代价**：多一个 dataclass 与一层解析。
- **换来**：两种风格都由同一套逻辑正确处理，且"越界目标不算节点"是显式规则而非巧合。

### D-2｜越界目标显式忽略

- **选**：`_key(path, module_root)` 抛 `ValueError`（目标不在 scope 内）时返回 `None`，边不成立。
- **为什么**：应用侧模块根在绝对基准**之内**，任何指向标准库/第三方/`src/` 下其他包的绝对导入
  都会"解析成功但不在图内"。治理侧因两者相同而天然不会越界——泛化后必须显式处理。
- **换来**：不会把外部依赖误当节点。

### D-3｜每个 scope 独立成图；先报先停

- **选**：按 `SCOPES` 顺序逐个建图检测；发现环即抛（与既有"首次违规即抛"行为一致）。
- **为什么**：跨 scope 的环不存在（两个 scope 是不同包），且分层规则已管跨层方向。
- **代价**：若两个 scope 各有环，一次只报第一个（与既有行为一致，不引入新语义）。
- **换来**：既有治理侧的调用行为逐字不变。

### D-4｜测试覆盖"应用侧形态"而不只是真实树

- **选**：新增应用侧形态的红/绿用例——绝对导入构成的环、跨子包的环、合法单向依赖、
  以及应用侧真实树无环的断言。
- **为什么**：D-1 描述的失败模式（绝对导入被静默漏掉）**只有在测试里用应用侧形态构造输入才能
  抓到**；只断言"真实树绿"会让一个漏掉全部绝对导入的实现也通过。
- **换来**：泛化的核心风险有直接守卫。

## Risks / Trade-offs

- [绝对导入解析基准写错 ⇒ 静默漏检] → D-4 的红例专门针对它：绝对导入构成的环必须被抓。
- [既有治理侧判定被泛化改动影响] → 既有 9 条用例与真实树断言必须全过；且治理侧 scope 的两个字段
  相同，等价于原行为。
- [扫描变慢] → 49 + ~20 个模块的 AST 解析；实测套件耗时增量可忽略（治理套件总时长在秒级）。
- [应用侧真实树意外有环] → 已先期取证为零环；若规则报红，先如实报告（走 bug 轨），**不**收窄范围。

## Migration Plan

1. `cycles.py` 引入 `Scope` 与 `SCOPES`，把解析拆成"绝对（按 absolute_base）"与"相对（按文件父目录）"。
2. 保留 `validate_no_import_cycles(root)` 的签名与抛出形状（facade 与既有测试不改）。
3. 新增应用侧形态用例 + 应用侧真实树断言。
4. 体积表跟实测；门禁；收口。

**回滚**：撤销 diff（scope 元组回到单个治理侧条目、删除新用例）。
