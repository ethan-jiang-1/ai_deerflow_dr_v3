# Design

## Context

动机见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| 账本已有守卫 | 状态词表（按面）· 名册（索引/解析）· 计数表 · 编号声明 · 表格放置 |
| `修复关联` 点名 change 是否存在 | **零检查**（全库 grep 零命中） |
| git 实测 | **6/6** 已修卡由"也动了 `_backlog/` 之外文件"的提交移入（含本会话四把） |
| 夹具现实 | 治理侧大量临时树**没有 git 历史**（`test_split_manifest` 等建的是无 `.git` 的树） |

## Goals / Non-Goals

**Goals:** 把"毕业翻转与实现同一把落地"钉成可执行规则 · 真实历史绿 · "卡独自提交"红 ·
无历史时沉默跳过 · 既有判定只增不改。

**Non-Goals:** 校验 `修复关联` 点名的 change 是否存在（判据更弱，留 follow-up）· 校验状态**时序** ·
改任何卡片或索引 · 非 git 场景。

## Decisions

### D-1｜规则读**历史**，不是读结构

- **选**：对每张已修卡，用 `git log --diff-filter=A --format=%H -- <path>` 找**首次加入**它的提交，
  再用 `git show --name-only` 取那笔提交改动的路径，要求**至少一个**不在 `_backlog/` 下。
- **为什么**：纪律的原话就是"**同一把落地**"——这是提交层面的事实，树层面看不见。树层面只能证明
  "卡在归档面、命名了对的 change"，证不了"和实现一起落地"。
- **代价**：规则依赖 git 历史（与其余树规则不同类）。
- **换来**：直接编码那条纪律本身，而不是它的弱代理。

### D-2｜无历史可判时**沉默**，不是失败

- **选**：没有 git 二进制（`OSError`）· `git log` 非零退出 · 卡未被跟踪（找不到添加提交）·
  `git show` 失败 ⇒ **全部跳过**。
- **为什么**：治理夹具建的是**没有历史的临时树**（`test_split_manifest` 的树就没有 `.git`）。
  一条在那里失败的规则，等于**把自己的盲区报成违规**——这正是 BUG-005 那类"静默失明"的反面病：
  "静默误报"。
- **代价**：真实历史之外的场景不受保护。
- **换来**：规则可被安全地放进 `validate_project()`，不会在夹具树上炸。

### D-3｜不接进 `--imports-only`

- **选**：与 `markdown_grammar` 同样只跑全量验证；`cycles` 是唯一两侧都跑的（它确属导入属性）。
- **为什么**：`--imports-only` 的语义是"只验证导入契约"；历史规则不属它。
- **换来**：flag 语义与实现一致，注释写明。

### D-4｜诚实标注它**不**证明的事

- **选**：模块 docstring 写明"共同落地是必要条件，但**不**证明那笔实现就是该 bug 的修复；
  卡与 change 的对应关系仍属 review 问题（由卡的 `修复关联` 一节点名）"。
- **为什么**：一条守卫的**边界**要写清楚，否则会被当成比实际更强的保证（本会话已两次强调
  "证明强度差异"）。
- **换来**：规则的保证范围与被保证的东西一致。

## Risks / Trade-offs

- [误报：卡片与无关实现同笔提交] → D-4 写明这是必要条件而非充分条件；真实历史上 6/6 合规，
  且这种误报方向是"放过"而非"误杀"。
- [在无 git 树上炸] → D-2 的四个跳过分支，且有一个专门的跳过测试与无 git 树测试。
- [历史被改写（rebase/squash）] → 规则读的是当前历史；改写后重新评估，属可接受。
- [规则自身顶格] → 75 行，独立入表。

## Migration Plan

1. 建 `graduation.py`（git 三问：首次加入的提交 → 那笔提交的路径 → 是否有 _backlog 之外的）。
2. 接进 `validate_project()`。
3. 直接测试：红例 · 绿例 · 两个跳过 · 真实历史。
4. 体积表 + 登记；门禁；收口。

**回滚**：撤销 diff（新模块删除、facade 撤掉一步）。
