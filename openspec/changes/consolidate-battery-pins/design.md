# Design

## Context

证据见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| 计数 pin 的手工代价 | 本会话改过 **3 次**（每次三个数字 + 一段散文） |
| 那段散文 | **自陈矛盾**（"30, not the 31 quoted when the change was planned" vs "32…13…45"） |
| 覆盖实测 | **9 条规则每条 ≥1 控制**；`adr_index` / `docs_scope` **各仅 1 条** |
| 哨兵 | `CLEAN_FIXTURE` 的 `rule == "violations"`，是 `run_rule` 里的**有意分支**（跑全套），不是坏引用 |

## Goals / Non-Goals

**Goals:** 判据换成它本来想守的不变量（覆盖）· 删掉自相矛盾的散文 · 新断言**能变红** ·
**一条控制都不退役** · 未来加控制不再需要手工同步计数。

**Non-Goals:** 退役控制 · 其他清单性质 · 父卡其余裁决项 · 产品代码。

## Decisions

### D-1｜判据是"覆盖"，不是"计数"

- **选**：`set(规则) ⊆ set(控制指向的规则)` —— 每条规则至少一条控制。
- **为什么**：计数 pin 真正想防的坏情况是**某条规则失去最后一条控制**（覆盖归零）。实测显示这个
  坏情况**真实存在风险**：`adr_index` 与 `docs_scope` **各只有 1 条**控制，删掉即零覆盖。覆盖断言
  恰好抓住它，而计数 pin 抓它只是"顺带"。
- **代价**：删掉一条**冗余**控制（如 18 条账本控制里的 1 条）不再被断言拦下。
- **换来**：判据与不变量一致；加控制不再收税。**D-2 说明这个代价为什么可接受。**

### D-2｜明说我们放弃了什么

- **选**：接受"冗余控制的丢失不被断言捕获"。
- **为什么**：那种丢失**不改变任何规则的可测性**（该规则仍有其他控制），且它在 git 里可见
  （删除是显式 diff）。而计数 pin 为这点微末保障收的税是**每次加控制都要改三处数字加一段散文**
  ——本会话已实测三次，且散文已经自相矛盾。**代价与收益不成比例。**
- **写入 docstring**：让后来者知道这是**有意的取舍**，而不是漏掉了"防丢失"。

### D-3｜哨兵必须被显式承认

- **选**：反向断言写成"除 `violations` 哨兵外，控制不得指向未知规则"。
- **为什么**：`CLEAN_FIXTURE`（"clean fixture must have zero violations"）**必须**跑全套检查，
  它指向哨兵是**正确**的。若不承认哨兵，这条合法控制会被新断言误报——那正是"守卫叫狼"。
- **代价**：断言里多一个显式的哨兵常量。
- **换来**：反向断言仍能抓到真正的坏引用（拼错规则名），而不误伤。

### D-4｜本把**不退役任何控制**

- **选**：只换判据，控制集一条不动。
- **为什么**：父卡的"剔除"针对的是**不必要的手工维护**，不是覆盖。这里的计数 pin 是纯判据，
  换成不变量即可，无需拿掉任何一条守卫。
- **换来**：本把的风险面只剩"断言写错"，而它有变异检查兜底。

## Risks / Trade-offs

- [新断言写成永真（例如规则集为空时通过）] → 断言同时要求**规则集非空**，且变异检查会红。
- [误伤哨兵控制] → D-3 显式承认；断言里哨兵是一个具名常量。
- [覆盖断言太弱，等于没守] → 变异检查直接用"仅 1 控制"的规则（`adr_index`）做红证。
- [删散文丢信息] → 被判据取代的信息（为什么是这些数）不再需要；**取舍本身**写进 docstring（D-2）。

## Migration Plan

1. 替换 `BatteryInventoryTests.test_inventory_counts_are_pinned` 为覆盖断言（含反向断言）。
2. 删掉自相矛盾的散文，写入 D-2 的取舍说明。
3. 变异检查（`adr_index` 的控制改指别处 ⇒ 必须红）。
4. 体积表按实测；门禁；父卡回写；收口。

**回滚**：撤销 diff（计数断言与散文恢复）。
