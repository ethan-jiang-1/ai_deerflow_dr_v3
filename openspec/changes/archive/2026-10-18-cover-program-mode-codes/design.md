# Design

## Context

证据见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| program 模式的真码 | **16**（`program.workstream` 是我 grep 到的前缀，不是码） |
| 上一把覆盖 | 4（正典绿例 + `workstream_count_invalid` / `mode_invalid` / `field_missing` / `workstream_registration_mismatch`） |
| 本把补齐 | **12**，全部落在 `_validate_program_proposal` 内部 |
| 校验顺序（决定夹具怎么写） | 工作流**数量** → 各工作流字段/seam/owner/候选 ID → **预算 vs 并集** 的比对 |
| 复用 | `test_project_gate.py` 的"按固定清单拷贝整棵树"模式（用于**调用方那层**，本把不做） |

## Goals / Non-Goals

**Goals:** 12 个码**逐码**覆盖（每条一个夹具旋钮 + 断言具体 code）· 既有 4 条不回归 ·
**实现 diff = 0** · 变异能红 · 不新增 skip。

**Non-Goals:** 调用方那层（`validate(root)` 的工作流 review 小节校验；需整棵树夹具，另开一把）·
改实现 · 产品代码。

## Decisions

### D-1｜夹具用"旋钮"而不是十二条各写一份提案

- **选**：`_workstream_body(owner, candidate_id, *, drop=…, extra=…)` +
  `_program_proposal(order=…, budget=…, alpha_id=…, beta_id=…, drop_program_field=…, alpha_body=…, beta_body=…)`。
- **为什么**：十二条各写一份完整提案会让"**只有一处不同**"这个关键信息消失在噪声里；旋钮让用例读起来
  就是"合规 + 这一处畸形"。也让正典绿例（无旋钮）成为同一份夹具的基线。
- **换取**：每条用例三行，且失败时能立刻看出是哪一处畸形导致的。

### D-2｜夹具必须让**更早的检查**全部通过

- **选**：为 `candidate_id_*` 两条保留**两个**工作流（不图省事写 `both=False`）。
- **为什么**：实测教训（偏差 1）——我先写了 `both=False`，于是"工作流数量"这条**更早**的检查先报
  `workstream_count_invalid`，把我要验的码挡在后面。**要验第 N 条检查，就必须满足前 N−1 条**。
- **换取**：每条用例真的打在它声称的那个分支上。

### D-3｜变异要**证明它真的施加了**

- **选**：变异脚本用锚点断言（锚点不匹配即中止），并且我核对"变异后哪条用例红"。
- **为什么**：实测教训（偏差 2）——变异 A 第一次因缩进不匹配**没有施加**，而套件报 `OK`；那一瞬间
  "OK" 看起来与"测试空洞"一模一样。**变异没施加与测试没价值，输出相同、含义相反。**
- **换取**：两个变异各自指名了它该红的用例。

### D-4｜调用方那层明确留给另一把

- **选**：本把只做 `_validate_program_proposal` 内的 12 个码。
- **为什么**：调用方那层（工作流 review 小节校验）需要**整棵树**夹具（config + change-guidance 树 +
  product 文档），成本与这半不在一个量级；混在一起会让本把的"穷尽一半"这个结论变模糊。
- **换取**：结论干净——"函数内的码已穷尽，跨层的那半如实记账"。
- **追记（2026-10-18）**：D-4 的前提**错了**——工作流级 review 校验不在调用方，且不需整棵树（每策略一个文档文件即可）。已由 `cover-program-workstream-reviews` 补齐。

## Risks / Trade-offs

- [十二条用例其实是同一个断言] → 每条断言的是**具体 code**（已由两个变异证明是承重的）。
- [夹具重构让既有 4 条失真] → 既有 4 条的参数语义保留（正典绿例仍无旋钮），且它们未改动地跑绿。
- [只测到"报了什么码"而没测"为什么"] → 这是单元级契约测试的固有边界；错误消息里的定位信息由
  既有用例（`detail` 含路径）覆盖。
- [调用方那层永远不做] → D-4 写明它被**移出范围而非取消**，并记入交付记录的未执行检查。

## Migration Plan

1. 重构夹具（旋钮化），既有 4 条改参数名。
2. 加 12 条；跑绿。
3. 两个变异各自指名；恢复字节一致。
4. 门禁；收口。

**回滚**：撤销 diff（夹具与 12 条用例删除，文件回到上一版）。
