# Design

## Context

动机见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| 目标 | `change_guidance_check/`（9 模块）——closeout 门禁的组件之一 |
| 探针 A 的端到端证明 | 在**合规的** proposal 里种一个围栏标题 → `[focus.field_missing]` exit 1（**误拒**）；修复后同一输入 **passed exit 0** |
| 三处逐行解析 | `helpers._section_after_heading` 的标题搜索 · `reviews` 的表格行收集 · `proposals` 的标题计数 |
| 第四处 | `guidance.py` 的 `> authority:` 计数（同为逐行正则、要求恰好 1 条） |
| 既有唯一实现 | `markdown_fences.py`（已被 closeout 工具、specs checker、doc-hygiene 采用） |

## Goals / Non-Goals

**Goals:** 四处改接唯一围栏规则 · 三条探针全部翻转 · 端到端误拒消失 · 真实树既有判定不变 ·
新增测试能红。

**Non-Goals:** 不改任何规则语义或消息文本 · 不把围栏规则声明进 spec · 不动其他脚本。

## Decisions

### D-1｜"遮蔽"而不是"重写每个正则"

- **选**：`helpers._without_fences(text)` = `markdown_fences.strip_fenced_code_blocks(text)` ——
  把围栏行清空、**保持行数**，然后**既有正则一行不改**地作用在遮蔽后的文本上。
- **为什么**：三处解析各有各的正则（标题、表格、计数）。逐个改成正则变体既啰嗦又容易漏；
  遮蔽把"结构感知"这件事收敛到**一个入口**，且行号不变（报错里的行号仍然准确）。
- **代价**：每次解析多一次文本处理（可忽略）。
- **换来**：正则保持原样 ⇒ 语义不被重写；新增的围栏感知只有一处实现。

### D-2｜`_section_after_heading` 必须走**行遍历**而不是遮蔽后按偏移切片

- **选**：对章节尾部逐行扫描，用 `fence_flags` 跳过围栏内的行，命中第一个真标题时按**原始文本**
  的偏移切片返回。
- **为什么**：遮蔽会**改变行长**（清空行内容），于是正则命中的偏移不再对应原始文本——照搬会
  返回错位的章节。这是"用遮蔽"在其他三处可行的同时、这一处必须走行遍历的原因。
- **代价**：一个 12 行的循环。
- **换来**：章节切片仍来自原始文本（下游按行读字段，位置不能错）。

### D-3｜`guidance.py` 的 `> authority:` 计数一并修

- **选**：同一模式（遮蔽后计数）。
- **为什么**：它与另三处**同类同风险**（逐行正则 + 要求恰好 1 条 ⇒ 围栏里引用一次即计数失真、
  误拒）。虽然我**没有**为它单独做端到端探针，但机制与探针 C 完全一致（同一函数、同一形状）。
- **代价**：一行改动。
- **换来**：这一整类在该 checker 内清零，而不是留下"看起来修好了"的第四处。
- **诚实标注**：这一处的判定依据是**机制同构**，不是独立探针（记入未执行检查）。

## Risks / Trade-offs

- [遮蔽改变行长导致偏移错位] → D-2 对唯一按偏移切片的地方改用行遍历；其余三处只做计数/筛选，
  行长无关。
- [既有判定被改变] → 真实树 checker 逐字仍为 `Change Guidance governance passed.`；治理套件
  241 条全绿（含端到端植入负例）。
- [测试夹具是手维护的依赖闭包] → 新依赖 `markdown_fences.py` 起初未被拷进临时树，
  **测试响亮失败**（`ModuleNotFoundError`）而不是静默通过——这正是该测试的价值；修复是把新依赖
  加进清单（D-4）。
- [上限被抬] → 三处按实测更正并留痕。

### D-4｜夹具的依赖闭包跟着实现走

- **选**：把 `markdown_fences.py` 加入 `test_project_gate.py` 的 `_FIXTURE_SOURCES`。
- **为什么**：那份清单是**手维护的依赖闭包**（与 `change_guidance_kernel.py` 必须留在顶层同一
  原因）。新依赖入册，临时树才会像真实树一样工作。
- **换来**：端到端植入负例继续有效（它现在覆盖到新的导入边）。

## Migration Plan

1. `helpers.py` 加 `_without_fences` + 改 `_section_after_heading` 为行遍历。
2. `reviews.py` / `proposals.py` / `guidance.py` 三处改接遮蔽。
3. 新增 5 条直接测试；变异检查。
4. 夹具依赖闭包补 `markdown_fences.py`；三处体积上限按实测更正。
5. 门禁；收口。

**回滚**：撤销 diff（四处回到逐行解析、删除新测试与夹具条目、上限回退）。
