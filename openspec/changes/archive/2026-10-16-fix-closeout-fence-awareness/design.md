# Design

## Context

动机见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| 缺陷 | `UNCHECKED_TASK_LINE` 逐行匹配、无代码块感知；围栏内的 checkbox 被当真任务 |
| 放大路径 | `_validate_review` 用"未勾任务标签"做子集校验 ⇒ 围栏里的示例标签被接受为合法任务引用 |
| 权威规则 | [CommonMark 0.31.2 §4.5](https://spec.commonmark.org/0.31.2/#fenced-code-blocks)；"闭合须同字符且不短于开启"见[规范讨论](https://cdn.commonmark.org/t/require-closing-fence-to-have-precisely-the-same-length-as-opening-fence/22/3) |
| 体积上限 | 该文件原为 256/256 **顶格**；本次修复加 39 行 |
| 闸给的出路 | 检查器原文："shrink it, or justify raising the ceiling with a one-line note next to the CODE_BUDGETS entry" |

## Goals / Non-Goals

**Goals:** 围栏内的 checkbox 不再算任务 · 反转后的测试能证明修复前会红 · 命令行契约与证据模式不变。

**Non-Goals:** 不跳过缩进代码块（见 D-3）；不拆这个文件（已登记 follow-up）；不动 CAS。

## Decisions

### D-1｜单趟行走，而不是"找配对围栏"

- **选**：一次遍历，维护 `open_fence` 状态；未闭合则余下全部视为代码。
- **为什么**：CommonMark 的围栏**允许不闭合**（余下全为代码）。任何"先找闭合行"的两趟写法
  在未闭合输入上都会退化成"整篇都是任务"，正是缺陷本身。
- **代价**：一个可变状态变量。
- **换来**：未闭合输入下的行为与规范一致，并由一条测试锁定。

### D-2｜闭合条件按规范严格实现

- **选**：同字符、长度**不短于**开启、其后**只允许空白**；开启允许 info string，但**反引号
  围栏的 info string 不得含反引号**（此时该行不是围栏开启）。
- **为什么**：三条都是规范明文；少了任何一条都会让合法文档被误判成"围栏外"，从而把示例当任务
  （回到缺陷）或把真任务当代码（漏掉真任务）。
- **换来**：6 条边界测试（更短闭合 / 带尾随文字 / info string / 波浪号 / 更长闭合 / 闭合后继续）。

### D-3｜**不**跳过缩进代码块（刻意的范围决定）

- **选**：只跳过围栏；四空格缩进的 checkbox **仍算任务**。
- **为什么**：四空格在 CommonMark 里确属"缩进代码块"（§4.4），但 `tasks.md` 的任务项合法地
  可以缩进四格（嵌套任务列表）。若在这里按规范严格处理，会**漏掉真任务**——那比当前缺陷更糟
  （缺陷是把示例当任务，后者是把任务弄丢）。
- **代价**：与全规范相比是有意的偏离。
- **换来**：一条测试把这个边界钉住，避免后来者"顺手统一"。
- **写明**：这是"刻意分歧就地写明 + 一条锁定它的测试"（仓规第 4 条）。

### D-4｜上限改到实测值 + 表内一行理由

- **选**：`FileBudget(max_lines=256 → 295)`，并在表内写一行理由（含 follow-up 指向）。
- **为什么**：闸自己给的合法出路就是这两条；缩回 256 等于删掉修复。上限保持"等于实测值"
  是这张表的既定规则（阶段 3 立表时即如此），改动会显式出现在 diff 里。
- **代价**：该文件的棘轮被抬起一次。
- **换来**：修复落地，且"该拆了"这件事在表里留痕（注释写明 2026-10-16 起可 import）。

## Risks / Trade-offs

- [把真任务误判为代码（漏任务）] → 闭合条件与 info string 规则按规范严格实现；6 条边界测试 +
  原有的三种项目符号/缩进测试共同守住；变异检查证明修复前会红。
- [未闭合围栏吞掉整篇] → 这正是规范行为，且有一条测试明确断言"余下全部视为代码"。
- [上限被抬起后失去约束力] → 表内注释写明理由与 follow-up；且长函数上限未动（新函数 < 50 行），
  下一次增长仍会触发闸。
- [卡片翻转与实现不同步] → 毕业翻转（`已修` + `git mv` + 两处索引 + 计数声明）与本实现同一把落地。

## Migration Plan

1. 实现 `_iter_outside_code_fences()`，接入 `_unchecked_task_labels()`。
2. 反转两条锁定测试为 11 条围栏覆盖。
3. 变异检查（对围栏失明 → 应红）。
4. 体积上限按实测更正 + 理由。
5. 卡片毕业翻转 + 索引/计数同步。
6. 门禁 + 归档。

**回滚**：撤销该 diff；卡片 `git mv` 回 `bugs/` 并翻回 `等人拍板`。
