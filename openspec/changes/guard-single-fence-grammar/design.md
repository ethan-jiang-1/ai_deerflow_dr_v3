# Design

## Context

动机见 `proposal.md` — Why。**取证塑造了这条规则的形态**：

| 事实 | 值 |
|---|---|
| 围栏语法被手写的次数 | **五次**（BUG-003/004/005/006 + BUG-003 修复当时新写的一份） |
| 朴素判据"代码里有反引号字面量即违规" | 真实树 **7 处假阳性**，全在 `doc_hygiene_battery/fixtures.py`，是**夹具内容**（文档片段） |
| 收窄判据"检测位置上出现该字面量" | 真实树 **0 处** |
| 手写围栏谓词的真实形态 | `re.compile(...)` 的 pattern · `line.startswith("```")` · `"```" in line` |

## Goals / Non-Goals

**Goals:** 规则零误报（真实树绿）· 三种手写形态全部落网 · 既有判定只增不改 · 新模块入表与登记。

**Non-Goals:** 改规范实现 `markdown_fences.py` · 改已修的四家 · 管非检测位置的反引号用法。

## Decisions

### D-1｜判据是"**检测位置**"，不是"出现字面量"

- **选**：只有当含 3+ 反引号/波浪号的字面量出现在**检测位置**时才违规：
  - 正则/搜索/切分类调用的实参（`compile`/`match`/`search`/`findall`/`finditer`/`sub`/`fullmatch`/
    `startswith`/`endswith`/`find`/`index`/`count`/`split`/`partition`）
  - `in` / `not in` 的**左操作数**
- **为什么（有实测依据）**：朴素版在真实树报 **7 处假阳性**——那 7 处是 `doc_hygiene_battery`
  构造夹具树用的**文档内容**（`"```\n"`、`"~~~\n"` 之类）。**会叫狼的守卫最后会被关掉**，
  所以判据必须区分"把围栏写成内容"与"把围栏写成谓词"。
- **代价**：判据依赖调用名与运算类型，不能只看字面量。
- **换来**：真实树零误报，而三种真实手写形态全部命中。
- **边界（写进模块 docstring）**：**非**检测位置的反引号字面量（夹具内容、错误消息）刻意不管——
  那正是 7 处假阳性的来源。

### D-2｜规范实现显式豁免

- **选**：`markdown_fences.py` 整文件豁免。
- **为什么**：它是**唯一被允许**知道围栏语法的地方；豁免写成一个具名常量，让"谁被豁免"成为
  可读的声明，而不是散落的 if。
- **换来**：规则的含义变成"除它之外，谁都不许手写"。

### D-3｜挂在架构 checker 里，沿用 `ContractViolation`

- **选**：检查全部治理侧 Python 模块（含子包——7 处假阳性就在一个包里，证明范围必须含包），
  违规报 `markdown.grammar_duplicated`，详情带 `文件:行号` 与指向规范实现的指引。
- **为什么**：既有 checker 的消费者（CI、closeout、测试）都按 `ERROR [code] detail` 读；
  沿用形状则零消费者改动，且既是"违规即可执行"的定位信息。
- **换来**：一条可操作的报错（哪个文件哪一行在重写围栏语法）。

### D-4｜测试必须覆盖"内容用法"的绿例

- **选**：绿例包含——把围栏字面量当内容写（夹具式）· 调用规范实现 · 规范实现自身 · 真实树。
- **为什么**：这条规则**最大的风险是误报**，而误报恰恰在"内容 vs 谓词"的边界上。只测红例会让
  一个"凡是反引号就报"的实现通过。
- **换来**：D-1 的边界有直接守卫。

## Risks / Trade-offs

- [误报夹具内容] → D-4 的绿例专门守它；真实树实测 0 命中。
- [漏报某种手写形态] → 红例覆盖三种真实形态（compile / startswith / in）；若将来出现第四种
  （例如 `.split("```")`），`split` 已在名单里。
- [检测位置名单太宽] → 名单只含"用字符串去查找/切分"的方法，不含普通 `str` 操作；且真实树 0 命中
  说明当前没有过宽导致的误报。
- [规则自身顶格] → 新模块独立入表。

## Migration Plan

1. 建 `markdown_grammar.py`：解析 → 找围栏字面量（排除 docstring）→ 判定检测位置 → 违规。
2. 接进 `facade.validate_project()`。
3. 直接测试：三红 + 四绿 + 真实树。
4. 体积表 + 登记；门禁；收口。

**回滚**：撤销 diff（新模块删除、facade 撤掉一步）。
