# Design

## Context

证据见 `proposal.md` — Why。塑造形态的实测事实：

| 事实 | 值 |
|---|---|
| 目标文件 | `portable_change_guidance_export.py`，**140 行** |
| 调用者 | **零**（CI / Makefile / gate / 七个 checker / 测试，五处全零） |
| 仅有的引用 | 自己的 `required-paths.toml` 登记 · `governance/README.md` 一行 · 父卡 · 一个归档 change 的历史 |
| 它的用途 | 校验"可移植导出给别的项目的候选包"——**别的项目**的需求 |
| program 模式（第 3 项） | **有一个真实用户**（2026-10-07 的 3 工作流 program）；**未使用时零成本**；无电池控制 |

## Goals / Non-Goals

**Goals:** 退役无调用者的组件（含登记与文档行，不留悬挂）· 更正父卡里那条**错误判断** ·
program 模式**一点不动** · 受管行数下降 · 门禁全绿。

**Non-Goals:** program/workstream 的任何改动 · 给它补控制（记为缺口，另开一把）· 父卡其余裁决项 ·
产品代码。

## Decisions

### D-1｜退役判据是"没有调用者"，不是"看起来像借来的"

- **选**：删掉 140 行 + 它的登记 + 它的文档行。
- **为什么**：它**占着"必需路径"的名分**（`required-paths.toml`）并出现在治理组件清单里，却不为本仓
  任何检查提供服务。**"被登记为必需"与"实际没人用"同时成立**，正是父卡要剔除的形态：它让装置显得
  比实际更大，并让后来者以为有个导出流程在跑。
- **代价**：若将来真要导出引导系统，需从 git 历史取回。
- **换来**：登记、文档、代码三者一致。

### D-2｜program/workstream 模式改为**保留**（更正上一轮的错误判断）

- **选**：不动它的一行代码/文档/config；在父卡把裁决从"退役候选"改为"保留"。
- **为什么**：它**有一个真实用户**（2026-10-07 的 3 工作流 program——`## Program Focus` +
  三个 `### Workstream Focus:`），是**唯一**的多工作流承载机制，而且**未使用时零成本**
  （校验只在 `if program_count or workstream_count:` 时激活）。我上一轮写"没有任何真实 change
  用过"是**错的**——错在只 grep 了 `## Program Focus` 的**出现文件数**就下了结论，没有去看那些
  文件里它是不是**真的被当成 program 用**。
- **代价**：约 99 行继续被携带。
- **换来**：不误删一个有用户的能力。**这条更正本身就是整理的价值**：父卡是权威记录，错的判断
  必须改，否则下一把会照着错的前提动手。

### D-3｜登记与文档必须与代码同时删

- **选**：三处同时改（文件、`required-paths.toml`、`governance/README.md`）。
- **为什么**：架构 checker 会校验登记路径**存在**（删文件不删登记 ⇒ 红）；而文档行指向已删文件
  是悬挂引用（父卡的硬约束）。上一把我已经因悬挂指针补过一次 fix-up，这次先做。
- **代价**：可能还要同步 `test_split_manifest.py` 的清单 pin（它按 owner 分组钉 required-paths）。
- **换来**：一次到位。

### D-4｜已知缺口如实记在父卡，不顺手扩张

- **选**：program 模式**零电池控制**这件事记为父卡上的缺口，**本把不补**。
- **为什么**：本把的裁决是"保留"，而补控制属于**新增覆盖**——与本轮"剔除"的方向相反，且应独立
  取证（是不是值得为 99 行、一个用户的分支加控制）。混在一起会让本把的边界模糊。
- **换来**：方向单一的改动（纯减法）+ 一条可追踪的缺口。

## Risks / Trade-offs

- [删文件忘删登记 ⇒ 架构 checker 红] → D-3；且 checker 会立刻报出来。
- [清单 pin 未同步 ⇒ 测试红] → 运行套件确认；若有 pin 则同步并在 Delivery Record 写明。
- [误删了被间接调用（如动态 import）的东西] → 取证已覆盖 CI/Makefile/gate/checker/测试五处；
  另用 `grep -rn` 全仓确认零引用。
- [父卡更正被当成"改口"] → 更正**写明原判断错在哪**（只数了出现文件数，没看是否真被当 program 用），
  不是含混改口。

## Migration Plan

1. `git rm` 目标文件。
2. 删 `required-paths.toml` 登记行与 `governance/README.md` 表行；`check_code_budgets.py` 若有条目则删。
3. 跑架构 checker、doc-hygiene、套件（按结果同步可能的清单 pin）。
4. 父卡：第 3 项更正为保留 + 第 4 项标记已执行 + 记已知缺口。
5. 体积表按实测；门禁；收口。

**回滚**：`git revert`（文件、登记、文档行、父卡更正一起回）。
