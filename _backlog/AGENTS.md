# _backlog AGENTS — 账本区门牌（薄：位置 + 走法 + 门票 + 词表，其余读手册）

> 规矩权威在 [README.md](README.md)（手册）；本门牌只保证落进本区的 agent 不用选择去读也能拿到
> 最低限度的法。事实单一来源：手册拥有事实；本门牌指路，摘录面（词表/门票）以手册为准。

## 位置（`_` 前缀 = 不在活跃队列，不是禁读）

- `issues/` — 活跃 issue（推敲 → 结论 → 交接）；完成进 `_archived/_settled_issues/`。
- `bugs/` — 活跃 bug（调查 → 修就绪 → 落修 → 确认）；修好进 `_archived/_fixed_bugs/`。
- `_archived/` — 归档（编号权威在 `_settled_issues/`、`_fixed_bugs/` 的 README 台账）。
- `_research/` — 留存外部系统分析（长寿命参照，不随卡迁移）。
- `methods/` — 常设方法库（按卡片步骤选方法，不占名册）。
- `triggers.md` — 活触发器索引（延后裁决的收口扫描面）。

## 走法与门票

- **issue**：四门走法与关闭条件四态见 [手册](README.md)；入线门票 =「方案与取舍」+「落地关联」
  填实（能写出一张 Change Focus）。
- **bug**：走法见 [手册](README.md)「一张 bug 怎么走」；修就绪门票 = 根因证据 + 修复方案 +
  `## 修好判据` 写就。P1/P2 修复型翻转自带撰写 propose 的授权；例外类别见手册第 3 步，走 owner。
- **唯一实施通道**是 OpenSpec change；拍板停在 propose 接受边界；一次放行一把。
- 卡上的状态与建议不授予实施权限（`修就绪` 的授权范围见手册铁律例外，2026-10-12）。

## 状态户口（首 12 行，`check_doc_hygiene.py` 强制）

- `issues/`：`推敲中` / `等人拍板`（+ 锚定字段 `毕业门`、`可关闭`、`类型`）。
- `bugs/`：`调查中` / `修就绪` / `已落修` / `等人拍板` / `待修`（+ `严重级别: P0/P1/P2`）。
- 翻转守卫见 [手册](README.md)「状态翻转法则」；`等人拍板` 不是完成词；已结 / 已修永不重开。

## 搬迁铁律

`git mv`（不是普通 mv），文件内容原样保留，位置即状态；搬完三处 README 联动（索引行 + 计数 +
Next-ID）。细节见 [手册](README.md)「搬迁规矩」。
